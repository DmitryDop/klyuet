# Клюёт — Отчёты (`reports.md`)

> Статус: спецификация MVP для реализации. 20 октября 2026.
> Связанные документы: `journal.md`, существующие продуктовые документы проекта и актуальные макеты Figma.
> Макеты: https://www.figma.com/design/WIFYiVA2QFFcDn0YYA1CCq/K?node-id=0-1

## 1. Назначение и границы

Отчёт описывает **конкретную рыбалку в конкретном месте**. Один пользователь может оставить несколько отчётов об одном месте; место может быть создано другим пользователем. Отчёт не равен месту и не создаёт новую точку на карте. **Координаты, тип места, платность и другие характеристики места принадлежат только сущности «Место» и не являются полями отчёта.**

В MVP: списки отчётов места и рыбака; просмотр своего и чужого отчёта; создание; редактирование и удаление своего отчёта (решение Дмитрия 25.10.2026, саммари QA-08/B — снимает прежний запрет «удаление отчёта не реализовывать»); состояния «с уловом / без улова», «с фото / без фото»; дата рыбалки; обратная связь об успехе, загрузке и ошибках.

## 2. Источники входа и маршруты

| Откуда | Действие | Куда |
| --- | --- | --- |
| Карточка места | Открыть отчёты | Список отчётов этого места |
| Список отчётов места | Открыть карточку | Детали выбранного отчёта |
| Список отчётов места / карточка места (если CTA предусмотрен макетом) | Добавить отчёт | Форма создания, место уже привязано |
| Журнал → Мои отчёты | Открыть карточку | Детали собственного отчёта |
| Чужой отчёт | Все отчёты рыбака | Список отчётов автора |
| Собственный отчёт | Редактировать | Форма редактирования |
| Детали отчёта | Перейти в место | Карточка связанного места. Кнопка показывается, только если отчёт открыт НЕ из карточки этого же места (прямо или через «Отчеты места»): место уже перед глазами — решение Дмитрия 22.10.2026; для входа из журнала кнопка сохраняется |

Навигационный стек сохраняет **источник входа**. «Назад» возвращает к предыдущему экрану (в том числе обратно в нужную вкладку журнала), а не всегда на карту. После успешного редактирования открыть обновлённые детали отчёта; после успешной публикации — созданные детали отчёта. Текущие списки обновлять при возврате.

У собственного отчёта нет дублирующего перехода «Мои отчёты»: они уже есть в журнале. Кнопка «Все отчёты рыбака» относится к чужому отчёту.

## 3. Данные отчёта

Минимальная смысловая модель (точные имена и типы согласовать с существующим кодом и схемой):

| Поле | Смысл |
| --- | --- |
| `id` | Уникальный идентификатор отчёта |
| `placeId` | Только ссылка на существующее место; при создании берётся из контекста, без копирования его характеристик |
| `authorId` | Автор отчёта (текущий пользователь) |
| `fishingDate` | **Дата самой рыбалки**, календарная дата без привязки к времени публикации |
| `publishedAt` / `createdAt` | Время публикации, служебное |
| `updatedAt` | Время последнего изменения, служебное |
| `catchStatus` | `with_catch` или `without_catch` |
| `fishSpeciesIds` | Список пойманных видов, пустой при `without_catch` |
| `fishingMethod` | Способ ловли: с берега / с лодки, если выбран |
| `tackle` | Снасть, если указана |
| `bait` | Приманка, если указана |
| `comment` | Комментарий, если указан |
| `photos` | Фотографии отчёта, может быть пустым |

**Граница сущностей:** отчёт хранит данные конкретной рыбалки и `placeId`. Координаты, платность, тип места, точность координат и правила редактирования места определяются только сущностью «Место» и её отдельной спецификацией. Не добавлять эти поля в модель, форму или редактирование отчёта. Название связанного места при необходимости отображать по `placeId`, а не копировать в отчёт. Имя автора получать по `authorId`.

**Открытый вопрос перед реализацией валидации:** окончательно не закреплена обязательность способа ловли и выбора вида рыбы при «С уловом». Рекомендация: способ необязателен; при «С уловом» требуется хотя бы один вид рыбы. Если существующий прототип работает иначе, не менять молча — сначала обозначить расхождение.

## 4. Создание отчёта

1. Форма открывается для конкретного `placeId`; выбранное место видно пользователю.
2. Состояние улова: «С уловом» / «Без улова». При «Без улова» выбор видов рыбы скрыт и значение видов не попадает в сохраняемый отчёт. При обратном переключении интерфейс ведёт себя предсказуемо; случайно скрытые виды не публикуются.
3. Поле **«Дата рыбалки»** обязательно, по умолчанию — сегодня по локальной дате пользователя. Можно выбрать прошлую дату в календаре, **будущие даты запрещены**.
4. Под датой быстрые чипсы: **Сегодня · Вчера · Позавчера**. Нажатие обновляет поле даты; ручной выбор даты синхронизирует выбранный чипс; если дата вне набора, активных чипсов нет.
5. Пользователь может задать способ ловли, снасть, приманку, комментарий и приложить фото согласно макетам.
6. Нажатие «Опубликовать отчёт» валидирует данные и запускает отправку.
7. При успехе открыть **созданный отчёт** и показать тост **«Отчёт опубликован»** уже на целевом экране.

Не добавлять дополнительные обязательные поля только по инициативе разработчика. Не делать автоматическую публикацию при выходе.

## 5. Просмотр отчёта

Поддерживать комбинации:
- свой / чужой;
- с уловом / без улова;
- с фотографиями / без фотографий.

В деталях показывать автора, **дату рыбалки**, **название связанного места** (с переходом в его карточку), результат рыбалки и заполненные сведения. **Не отображать координаты, тип и платность места как информацию самого отчёта**: всё это пользователь смотрит в карточке места. Пустые необязательные секции скрывать. Галерея показывается только при наличии фото. Если видов рыбы много, раскрывать полный список по согласованному образцу карточки места (не придумывать новый паттерн).

Редактирование доступно **только автору**, проверка должна выполняться и на серверной стороне. У чужого отчёта нет элементов редактирования.

## 6. Редактирование и выход

- Открыть существующий отчёт, предварительно подставив сохранённые значения, включая дату рыбалки, фото и статус улова.
- Сохранение обновляет ту же сущность, **не создаёт новый отчёт**.
- При успехе открыть обновлённый отчёт и показать тост **«Изменения сохранены»**.
- Если пользователь нажал «Назад» и **ничего не менял**, вернуться сразу.
- Если есть реальные несохранённые изменения (dirty state), показать общую модалку:
  - Заголовок: **«Выйти без сохранения?»**
  - Описание: **«Введённые данные будут потеряны.»**
  - Кнопки: **«Остаться»** (закрывает модалку, форма остаётся), **«Выйти»** (отменяет изменения и возвращает назад).
  - Крестик эквивалентен «Остаться».
- Такая же модалка используется при выходе из **нового заполненного** отчёта. Предустановленная сегодняшняя дата сама по себе не делает форму изменённой.
- Автосохранение черновиков в MVP не предусмотрено.

### Удаление собственного отчёта

- Доступно **только автору** отчёта; у чужого отчёта элементы удаления не показываются.
- Проверка авторства выполняется **не только интерфейсом**: сервисный слой (репо) отклоняет удаление чужого отчёта независимо от состояния UI.
- Вход в удаление — меню «⋯» на деталях своего отчёта (пункт «Удалить»; иконка карандаша в тулбаре обновлена Дмитрием 25.10.2026 на «⋯», K `156:8408`); состав меню и подтверждение — по паттерну карточки места (K `436:12522`): шторка «Изменить»/«Удалить», затем модалка **«Удалить отчёт?»** с кнопками «Оставить» / «Удалить».
- При успехе: тост **«Отчёт удалён»**, возврат к источнику входа (карточка отчёта больше не существует). Связанное место не удаляется.
- Списки, содержащие отчёты (журнал «Мои отчёты», «Свежие отчеты» и «Все отчеты» карточки места, «Отчеты рыбака», применённые фильтры карты), обновляются при возврате на них.

## 7. Сортировка и даты

- Все списки отчётов сортировать по **`fishingDate` по убыванию**, новые рыбалки сверху.
- Отчёт о рыбалке трёхмесячной давности, опубликованный сегодня, размещается по дате самой рыбалки, **а не вверху списка**.
- При одинаковой дате рыбалки использовать дату публикации как вторичный ключ (поздние публикации выше).
- Дату публикации хранить отдельно; не подменять ею дату рыбалки на карточках.
- После редактирования даты пересчитывать положение отчёта в списках.

## 8. Загрузка, успех и ошибки

### Общий подход

| Событие | Обратная связь |
| --- | --- |
| Первичное получение списков отчётов и деталей | Skeleton, геометрия соответствует реальному контенту |
| Получение данных при входе в редактирование | Состояние загрузки, не показывать недостоверную пустую форму |
| Публикация или сохранение изменений | Лоадер в кнопке, повторные нажатия заблокированы |
| Успешная публикация | Переход в отчёт → тост «Отчёт опубликован» |
| Успешное редактирование | Переход в обновлённый отчёт → тост «Изменения сохранены» |
| Ошибка публикации | Модалка «Не удалось опубликовать отчёт» с действиями повторить / вернуться к заполненной форме |
| Ошибка редактирования | Модалка «Не удалось сохранить изменения» с теми же действиями |
| Ошибка загрузки списка/деталей | Понятное состояние ошибки и действие «Повторить»; без бесконечного скелетона |

- Пока идёт отправка, повторный submit запрещён; форму не изменять, выход заблокировать, пока запрос не завершился (согласно согласованному состоянию формы).
- Поля и локально выбранные фотографии должны переживать сетевую ошибку и повторную попытку.
- Нужна **серверная идемпотентность публикации**: повторный запрос после потерянного ответа не создаёт дубликат.
- Skeleton: цвета текущей темы, мягкая пульсация, без искусственных задержек и агрессивного shimmer.
- Полноэкранный лоадер — для инициализации приложения, **не** вместо скелетонов отчётов и **не** вместо лоадера кнопки.
- Компонент Toast единый для приложения, автоматически исчезает примерно через 3 секунды, без кнопки и крестика. Ошибки отправки показывать модалкой, а не тостом.

## 9. Критерии приёмки MVP

- [ ] Отчёт привязан к существующему месту, в том числе чужому, только через `placeId`.
- [ ] В отчёте нет полей координат, платности, типа места или точности координат; эти данные доступны через карточку места.
- [ ] Вход из карты и из журнала возвращает пользователя по правильному стеку.
- [ ] Собственный отчёт редактируется, чужой — нет.
- [ ] Состояния с уловом/без улова и с фото/без фото отображаются корректно.
- [ ] Быстрые даты и календарь синхронизированы; будущая дата недоступна.
- [ ] Данные сортируются по дате рыбалки, в том числе после редактирования.
- [ ] Модалка выхода возникает только при несохранённых изменениях.
- [ ] Loading/ошибки не стирают данные, повторное нажатие не создаёт дубликатов.
- [ ] После успеха происходит переход в отчёт и показывается корректный тост.
- [ ] Светлая и тёмная темы поддержаны существующими токенами.
- [ ] **Было → Стало:** каждый ранее работавший сценарий продолжает работать после обновления.

## 10. Backlog — НЕ реализовывать в MVP

- Удаление собственных отчётов; в дальнейшем определить подтверждение удаления и последствия для списков.
- История изменений отчёта и возможность просматривать её другим пользователям.
- Расширенная аналитика по сезонам, видам рыбы и динамике клёва.
- Автосохранение и восстановление черновиков, если это подтвердится необходимостью на тестах.

**Правило для Claude Code:** раздел Backlog — список идей на будущее, не инструкция к реализации. Не реализовывать без отдельного решения владельца продукта.

## 11. Инструкция по внедрению

Сначала изучить текущий код, маршруты, данные, дизайн-токены и существующий интерактивный прототип. Не переписывать работающую логику вслепую. Сверить Figma с текущим поведением; при противоречии между этим документом, макетами и кодом — сообщить и запросить решение. Использовать существующие компоненты и паттерны. Перед завершением пройти критерии приёмки и регрессию.
