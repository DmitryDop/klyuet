# User Flow v1 — «Клюёт»

## 1. Главный сценарий — выбрать место для рыбалки

**Старт**

Пользователь открывает приложение.

↓  

### Карта

Пользователь видит рыболовные места в текущей или выбранной области карты.

Возможные действия:

- двигать карту;
- изменить масштаб;
- открыть фильтры;
- выбрать точку;
- открыть сохранённые места;
- добавить отчёт или новое место.

↓

### Нужно сузить выбор?

**Нет**  
→ выбрать точку на карте.

**Да**  
→ открыть фильтры.

↓

### Фильтры

Пользователь может выбрать:

- вид рыбы;
- свежесть данных;
- платное / бесплатное;
- берег / лодка.

↓

### Карта с результатами

Отображаются подходящие места.

↓

### Выбрать место

Пользователь нажимает на точку.

↓

### Preview места

Короткая карточка поверх карты:

- название;
- тип места;
- основные виды рыбы;
- свежесть последней активности;
- платно / бесплатно.

↓

### Интересно?

**Нет**  
→ закрыть preview → вернуться к карте → выбрать другое место.

**Да**  
→ открыть полную карточку.

---

## 2. Карточка места — принять решение

### Карточка места

В первом экране пользователь видит:

- название;
- местоположение;
- свежесть данных;
- какие виды рыбы ловили;
- когда был последний отчёт;
- платное / бесплатное;
- берег / лодка;
- доступ / подъезд.

↓

### Есть свежие отчёты?

**Да**  
→ показать последние отчёты.

**Нет**  
→ явно показать:

**«Свежих отчётов пока нет»**

и дату последней известной активности.

↓

### Последние отчёты

Пользователь смотрит:

- дату;
- вид рыбы;
- результат;
- фотографии;
- короткий комментарий;
- дополнительные данные при наличии.

↓

### Место подходит?

**Нет**  
→ назад → карта → выбрать другое место.

**Да**  
→ возможные действия:

- сохранить место;
- открыть маршрут;
- посмотреть ещё отчёты.

↓

### Построить маршрут

Маршрут открывается во внешнем навигационном приложении.

↓

**Конец сценария выбора**

Пользователь принял решение, куда ехать.

# 7. Сценарий — приватная точка

**Да**

# 8. Сценарий — нет свежих данных

Пользователь открывает место.

↓

### Последний отчёт устарел

Например:

**Последний отчёт — 8 месяцев назад**

↓

Приложение не делает вывод:

**«здесь хорошо клюёт»**

↓

**«Свежих данных нет»**

↓

Возможные действия:

- посмотреть похожие места рядом;
- вернуться на карту;
- сохранить место;
- оставить отчёт после собственной поездки.

# 9. Основной Happy Path

Самый важный сценарий первого прототипа:

**Открыть приложение  
→ Карта  
→ Фильтр по рыбе  
→ Выбрать место  
→ Увидеть свежесть  
→ Посмотреть последний отчёт  
→ Решить ехать  
→ Сохранить  
→ Открыть маршрут**

---

# 10. Второй Happy Path

UGC-сценарий:

**После рыбалки  
→ + Добавить  
→ Отчёт  
→ Выбрать место  
→ Рыба  
→ Результат  
→ Фото  
→ Приватность  
→ Опубликовать**

---

# 11. Что проверить прототипом

При тестировании user flow нужно понять:

1. Понимает ли пользователь карту без объяснений.
2. Замечает ли он свежесть информации.
3. Использует ли дату отчёта при выборе места.
4. Понимает ли разницу между:
   - «рыба здесь водится»;
   - «эту рыбу здесь недавно ловили».
5. Может ли пользователь выбрать место без чтения длинных текстов.
6. Понятна ли механика приватности.
7. Готов ли пользователь оставить отчёт после рыбалки.
8. Не слишком ли длинный сценарий публикации отчёта.
9. Нужен ли отдельный раздел «Сохранённое».
10. Возвращается ли пользователь на карту естественным образом, если место ему не подходит.

# Главный принцип User Flow

Весь продукт строится вокруг двух циклов.

### До рыбалки

**Найти → проверить актуальность → принять решение**

### После рыбалки

**Зафиксировать результат → обновить актуальность данных**

Именно второй цикл поддерживает первый.

Чем больше реальных свежих отчётов появляется после поездок, тем полезнее становится карта для следующего пользователя.
