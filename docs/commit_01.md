## 2. Что реализовано

- **Навигация** (коммиты 8a0b8fb/1f65635): табы Карта/Журнал/Профиль по K-DS tab_bar 68:327; карточки и формы — следующие этапы.

- **Маркеры**: точные места — location-dot (56×56, токен-заливки); приблизительные — географические окружности радиуса 1000 м (спека §3.1): заливка #176b5233, пунктирная граница #176b52, толщина 0.5 (dimensions/stroke/05), паттерн [5, 4]; центральный пин скрытой точки не отображается («Клюёт» §2).
- **Кластеризация**: supercluster (JS-слой — нативная кластеризация к Apple Maps подключена быть не может, техотчёт этапа 03), три вида по спеке §1.1: точные (Default), приблизительные (Dashed), смешанные (Dashed_Extra), 48×48; цифра = количество мест; тап — увеличение на уровень, без шторок.
- **Контролы**: поиск/фильтр/слои (верхняя колонка справа), гео и «+» action (нижняя), легенда точности — по компоновке актуальных экранов K; действия, кроме масштаба, отрисованы, но не подключены (без имитации работоспособности).
- **Onest**: вариативный TTF подключён через expo-font; загрузка до первого рендера, сплеш закрывается после готовности; токены K-DS в `typography.ts`.

## 3. Ключевые технические решения

- `Place` в типах не содержит исходные скрытые координаты приблизительных мест — клиентская кластеризация выполняется только над публичными данными (подтверждённая модель приватности, критерий 6 спеки).
- Кластеризация на MapKit — только через supercluster: нативная кластеризация на Apple Maps вызывает runtime-исключение (подтверждено документацией).
- Кластеренные вьюхи — `tracksViewChanges={false}` (документированная оптимизация rnmaps).
- Зум: MapKit — по `altitude`, Google — по целочисленному `zoom`; пересчёт кластеров только на `onRegionChangeComplete`.
