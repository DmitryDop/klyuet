## 2. Обратная совместимость

- В отчётах хранятся **названия** (`fishSpeciesIds` = строки-названия, `tackle` = строка) — существующие fixtures/demo-отчёты работают без миграции.
- Все демо-значения снастей из справочника: «Спиннинг», «Поплавочная снасть» в fixtures совпадают; единственное — в `demo-report-6` значение «Донка» уточнено на «Донная снасть» (demo-фикстура, не пользовательские данные): старое значение отсутствовало бы в утверждённом перечне и терялось бы при редактировании — правило задачи §2.
- Виды из fixtures, ранее отсутствовавшие в справочнике («Плотва», «Подуст»), теперь входят в перечень — редактирование старых отчётов не теряет виды.
- Порядок первых 13 видов сохранён; новые — после K-блока.

## 4. Известные ограничения

1. Справочники локальные; серверная синхронизация/идемпотентность публикации — при появлении бэкенда.
2. Классификация рыб — рыболовная классификация, при появлении серверного справочника уточняется по нему.
3. Демонтаж маршрута `/author-reports/[id]` (не вызывается после шторки по navigation.md) — при отдельном решении.
4. `app.json` не содержит плагины/строки разрешений пикеров standalone-сборки — дополнить при первом build вне Expo Go.
