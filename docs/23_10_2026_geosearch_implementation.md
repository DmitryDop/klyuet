- **§6** debounce 300 мс; свежий запрос выигрывает (последовательность + abort устаревшего); лимит 10; сортировка Photon — релевантность name, близость слабым bias; не ограничено видимой областью.
- **§7** расстояние — haversine по прямой, км; отсчёт от фейк-геопозиции; разрешение не запрашивается; без позиции код расстояния не показывается (сейчас позиция фейковая и есть всегда).
- **§8** выбор: commit цели → закрытие поиска (`router.back()`) с dismiss клавиатуры → камера карты уезжает на extent пункта (минимум 0.02°) или по типу: state/city 0.25/0.2°, town 0.08°, прочее 0.03°. Карточка/пины/создание автоматически не открываются; метки и кластеры пересчитываются картой сама по новому региону.
- **§9** закрытие без выбора: push не меняет карту (карта смонтирована), центр/масштаб/фильтры сохраняются; повторный вход — с пустого поля (state экрана пересоздаётся), истории нет.
- **§10** не затронуты: навигация, кластеризация, координаты мест, фильтры, карточки, добавление места (кнопка поиска шага 1 — прежняя заглушка), K-DS.

## Известные ограничения и решения на уточнении

1. **Photon — публичный демо-сервер** (photon.komoot.io): fair-use троттлинг, без SLA; для продакшна — свой экземпляр (open source, ~95 GB) или платный API. Порядок выдачи частичных запросов крупных городов может отличаться от ожидаемого («Мос» ставит «Мостово» выше «Москвы» из-за bias близости —bias слабый, расстояние от демо-геопозиции).
2. **Макеты vs данные:** в макете первая ячейка «село Кочкурово» с префиксом типа, у остальных — без; Photon не отдаёт русские слова типов, префикс не реализован — различение одноимённых дают регион и расстояние. Регион из OSM/Photon — «Мордовия» (в макете «Республика Мордовия»).
3. **Верх экрана:** в макете панель на 16 от края при скрытой строке состояния; реализовано `insets.top + 16` (прецедент тулбаров экранов).
4. Состояния «Ничего не найдено» / ошибки / «Повторить» — макетов в K нет; тексты — по ТЗ, стилизация минимальная (Body S / labelL, токены).
5. **Сторожение зависимостей (важно):** во время неудачного запуска `npx expo start` (17:15, попытка подъёма сервера для проверки — уже прервана по вашему стопу) проверка версий Expo сама переписала `package.json`/`package-lock.json`. Полный перечень изменений lockfile:
   - **понизила `react-native-maps`: 1.29.11 → 1.27.2** и закрепила без `~` — SDK 57-ожидание Expo; карта теряет два минорных релиза;
   - патч-бампы внутри SDK 57: expo 57.0.28→31, @expo/ui 57.0.23→26, expo-router 57.0.26→29, expo-linking 57.0.12→13, expo-constants, expo-asset, expo-modules-core/core/-jsi/-autolinking/@expo/cli/-router-server, babel-preset-expo и др. (см. diff);
   - uuid 7.0.3 снят с верхнего уровня, добавлен вложенный @expo/json-file 11.2.1; xcode 3.0.1→4.0.0.
   Я обновления не запускал сознательно. Предлагаю `git checkout -- package.json package-lock.json`; node_modules, если Expo успел их обновить, можно вернуть `npm ci` (требует сети). Не делал ни того, ни другого без разрешения.
