## 3. Зависимости и технический долг

- RN-зависимости SDK-57-совместимые, но нет ни одной, нужной продукту: нет карты (`react-native-maps`/mapbox), нет `expo-location`, нет `expo-image-picker`, нет хранилища (SQLite/AsyncStorage), нет HTTP-клиента/бэкенд-SDK.
- `NativeTabs` из `expo-router/unstable-native-tabs` — нестабильный API; шаблонные табы будут заменены под Figma V2.
- React Compiler + `typedRoutes` включены в шаблоне — учесть при миграции.
- Нет тестов, нет ESLint-конфига (только `expo lint`), нет CI.
- Прототип грузит Leaflet с unpkg CDN — для RN не переиспользуется.

## 4. Главные архитектурные риски

1. **Продукт мультипользовательский, бэкенда нет.** Отчёт на чужом месте, Журнал «мои отчёты», блокировка редактирования места после первого чужого отчёта, privacy-safe координаты — всё это невозможно локально. Решение продуктовой команды: (а) локальная single-user демо-версия, (б) BaaS (Supabase и т.п.), (в) свой бэкенд.
2. **Картографическая библиотека не выбрана.** Варианты: `react-native-maps` (нативная, OSM-тайлы через `UrlTile`), Mapbox/векторные тайлы (лучше стилизация), Leaflet в WebView (максимальный перенос, но тормознуто).
3. Сущности «место» и «отчёт» нельзя смешивать — закреплено в `journal.md`/`reports.md`; модель данных RN должна это фиксировать с первого дня.

## 5. Неоднозначности и конфликты между документацией, макетами и кодом

1. **Preview места.** `user_flow.md` §1 — preview-шторка перед полной карточкой. `map-place-flows-mvp.md` §2 — «превью, промежуточных шторок нет», тап сразу открывает карточку. Прототип реализует второе. user_flow.md не помечен как устаревший.
2. **Раздел «Сохранённое».** `product-foundatio.md` §06.8 и навигация «Карта / Сохранённое / Профиль» — в MVP. Figma V2 и `journal.md` — «Карта / Журнал / Профиль», где «Мои места» ≠ сохранённые. Сохранённые места выпали из MVP молча.
3. **Способ ловли у места.** В прототипе у места есть поле `fishing` (берег/лодка), карточка его показывает, но форма создания места его не собирает (созданное всегда `fishing: 'shore'`). `reports.md` относит `fishingMethod` к отчёту. Откуда берётся характеристика места — не зафиксировано.
4. **Дата рыбалки.** `reports.md` требует обязательное поле `fishingDate` с чипсами и календарём. В прототипе отчёт всегда «Сегодня» (`daysAgo: 0`). Механика §4/§7 reports.md не прототипирована.
5. **Редактирование места при наличии отчётов.** `journal.md` §3: координаты/тип/платность фиксируются, название/описание правятся. Прототип: карандаш исчезает полностью.
6. **CTA второго шага создания места.** `map-place-flows-mvp.md` §3.2 — «Опубликовать» во всех состояниях. Прототип — «Опубликовать место» / «Сохранить изменения».
7. **Два Figma-файла.** `docs/v2.md` ссылается на `AdQjv6kqqQG7IMjOAiW62k` (файл опустел), актуальный — `WIFYiVA2QFFcDn0YYA1CCq`. v2.md не обновлён.
8. **Справочник рыбы.** Прототип: места ссылаются на `Плотва` и `Карп`, которых нет в справочнике `FISH` (13 видов) — фильтр по ним недоступен. Где канонический список видов?
9. **Токены/тема.** `reports.md` §9 требует светлую/тёмную темы «существующими токенами» — токенов в RN-шаблоне нет.
10. **Модалки выхода** («Выйти без сохранения?», «Отменить создание места?», крестики, системный «Назад») — описаны в спеках, в прототипе отсутствуют.
11. **«Все отчёты рыбака»** у чужого отчёта (reports.md §2) — экрана нет ни в прототипе, ни в доступных макетах.

## 6. Расхождения: карта HTML-прототипа ↔ утверждённые решения (map-place-flows-mvp.md)

### A. Прототип не соответствует утверждённой спеке — в RN не переносить

| # | Пункт спеки | Прототип | Последствие |
|---|---|---|---|
| A1 | Кластеризация: 3 типа (точные/приблизительные/смешанные вариант А), 40×40 экранных единиц, цифра = число мест, тап → zoom → раскрытие, без промежуточных шторок (§1.1, P0) | Кластеров нет вообще; все объекты поштучно (pin/circle) | Писать в RN по спеке с нуля |
| A2 | Приватность координат: клиенту не передаются исходные точные координаты приблизительных мест (§1.1) | Настоящий центр круга лежит в локальных данных | Требование к бэкенду/репозиторию; отображать из «публичного представления» |

### C. Совпадает с утверждённым — поведение переносить можно

- Тап по пину и по любой области приблизительного места → сразу полная карточка, без preview; центрального пина скрытой точки нет (§2).
- Возврат сохраняет центр, масштаб и фильтры (§2, критерий 5) — проверить в RN, что expo-router не пересоздаёт экран карты.
- Приблизительная область — географическая окружность ~1 км с пунктиром, масштабируется, может уходить за экран (§1.1).
- Состав и расположение контролов совпадают с текущим макетом 1:670.
- Двухшаговое создание места с сохранением ввода между шагами и возвратом к координатам без потери формы (§3.1–3.2) — работает после несмерженного фикса `changeCoords()`.

### D. Визуальное (не поведение)

- Прототип не в цвете актуального макета: пин `#14181c`, кнопка «добавить место» `#242424`; в Figma 1:670 — зелёный акцент. Цвета в RN брать из Figma/токенов.
- Источник тайлов для RN — отдельное решение (входит в выбор карт-библиотеки).

## 7. Рекомендуемая архитектура MVP (минимальная, RN + Expo)

```
src/
├── app/                    # expo-router: (tabs)/map, (tabs)/journal, модальные экраны
│   ├── place/[id].tsx      # карточка места
│   ├── report/[id].tsx     # детали отчёта
│   ├── report-form.tsx     # создание/редактирование отчёта (placeId, reportId?)
│   ├── add-place/coords.tsx, add-place/desc.tsx, add-place/access.tsx
│   └── filter.tsx, fish-sheet.tsx, tackle.tsx
├── data/                   # места/отчёты: типы TS + репозиторий
│   ├── types.ts            # Place, Report — сущности раздельно, placeId только ссылка
│   ├── demo-data.ts        # порт data.js (исправить справочник рыбы)
│   └── repo.ts             # интерфейс getPlaces/getReports/createReport/... — точка подмены на бэкенд
├── logic/                  # чистые функции — почти 1:1 порт из app.js
│   ├── filters.ts, dates.ts (rDateStr, склонения), sort.ts
└── ui/                     # кнопки, чипсы, пикеры-списки, Toast, skeleton
```

Принципы: сущности Place/Report раздельно; фильтрация/сортировка/даты — чистые функции в `logic/`; репозиторий скрывает источник данных; навигация через expo-router вместо рукописного стека прототипа.

### Этапы разработки

Каждый этап короткий, с проверкой `npx tsc --noEmit` + `npx expo lint` + прогон сценария в Expo Go.

1. Контрольная точка — закоммитить текущее состояние (app.js, CLAUDE.md, UX/).
2. Каркас навигации — табы по Figma V2 (Карта/Журнал/Профиль-заглушка), чистка шаблонного кода.
3. Данные и логика — `types.ts`, порт `demo-data.ts` и `logic/*`, мини-тесты фильтров/дат.
4. Карта + чипсы — после выбора карт-библиотеки; первый вертикальный срез.
5. Карточка места → отчёты → детали отчёта (чтение, возврат сохраняет центр/фильтры).
6. Форма отчёта (создание + редактирование) + дата рыбалки + модалка dirty-exit.
7. Создание места — 2 шага, подтверждение отмены.
8. Журнал — обе вкладки, пустые состояния, тосты.
9. Фильтр — полный экран (механика из прототипа).
10. Хард-требования спеков — кластеризация, skeleton/ошибки, идемпотентность (при наличии бэкенда).

Первый рабочий сквозной сценарий (этапы 1–5): карта → тап пина → карточка с отчётами → «Назад» → прежняя карта.

### Первая конкретная задача кодирования

Этапы 1–2: закоммитить контрольную точку; вычистить шаблон (`explore.tsx`, demo-компоненты сплеша); создать таб-навигацию Карта / Журнал / Профиль (профиль — заглушка-тост); перенести SVG-иконки таб-бара из прототипа в `assets/`; порт `theme.ts`.

Проверка: `npx expo start` → приложение открывается на карте-заглушке, три таба переключаются, `npx tsc --noEmit` чист.

**Блокеры до начала:** выбор карт-библиотеки, решение по бэкенду (или явный старт с локальным single-user), ответы на спорные пункты §5 и вопросы B1/B2.
