## Механика

- Формулы в обеих формах одинаковые (локально, без общего хука — по прецеденту
  дублирования форм):
  - `scrollFieldAboveKeyboard(y, h, kb)`: цель — низ поля над видимой
    областью `screenH − kb − 72` (72 = pt 16 + кнопка 48 + pb 8 — панельная
    константа существующего резерва контента `paddingBottom: kb + 72`);
    скролл только если низ поля перекрыт (target > 0) — видимые поля не дёргаются;
  - `onFocus`: поле запоминается; если клавиатура уже открыта (переключение
    поля к полю) — скролл сразу;
  - `keyboardWillShow`: высота — в state и ref; скролл — в эфффекте
    `[keyboardHeight, inputFocus]`, который выполняется ПОСЛЕ commit'а
    reserve-контента: прямая отправка scrollTo из события гонялась с
    рендером reserve — contentSize менялся после скролла и offset сжимался
    (воспроизведено в симе, правка откачена; прецедент 60-мс-скролла не
    потребовался — порядок гарантирует effect после commit);
  - onLayout полей измерен на обёртках FormField (координаты относительно
    контента ScrollView, как у прецедентных nameFieldY/speciesFieldY);
  - scrollOffset — ref из `onScroll` (throttle 16), без перерисовок.
- Панель кнопки над клавиатурой / резерв контента — существующие, не менялись.

## Проверки

- `npx tsc --noEmit`, `npm run lint` — чисто (0/0).
- Холодный запуск в симе — карта/маркеры/тосты без изменений.
- **Цепочка «тап → клавиатура → подскролл» визуально не подтверждена**:
  headless-симулятор (без Simulator.app) не показывает нативную клавиатуру;
  имитации (autoFocus/temp-tap/тестовая высота 336) дают mount-артефакты,
  которых нет при реальном тапе. Приёмка тапами за Дмитрием:
  тап на «Что происходило?»/«Приманка» внизу формы при закрытой клавиатуре,
  затем на «Приманка» при открытой (переключение без закрытия).
